# Build a bounded and testable decoding contract

Define each field using transport, device identity, firmware range, message identifier, byte or bit range, encoding, signedness, scale, offset, unit, validity rule and source-document revision. Include whether it is readable, writable, reserved, volatile or latched. Keep an unknown value distinct from numeric zero and a stale value distinct from a current valid sample. A protocol parser should return raw bytes and structured diagnostics when a field cannot be interpreted safely.

For a signed integer stored in `n` bits, interpret two's complement only after extracting the exact unsigned field: values at or above `2^(n-1)` map to `u-2^n`. Then apply the vendor's scaling and offset in the documented order, commonly `physical = raw * scale + offset`. Test minimum, maximum, negative and sentinel values. A sentinel such as all ones may mean unavailable rather than the maximum measurement. Never clamp it into a plausible physical range without recording invalid status.

Distinguish byte endianness within a word from the ordering of words in a wider application value. For two 16-bit registers representing IEEE-754 binary32, verify the manufacturer's ordering and use a known reference value, not the most plausible of several guessed interpretations. NaN and infinity require explicit treatment. Preserve integer precision when counters exceed JavaScript's safe integer range; use bigint or a decimal representation through serialization.

Bit numbering in DBC-style signal descriptions can be convention-sensitive, especially for big-endian signals crossing byte boundaries. Use a documented reference decoder and a fixture with independently known physical values before accepting an implementation. Multiplexed frames require the selector to be decoded before choosing the payload schema. Reject unsupported layouts instead of interpreting every frame through the first known message type.

Validate framing before allocating from declared sizes. Bound frame length, nesting, outstanding requests, receive buffers and resynchronization work. Correlate request and response identifiers, handle exception responses distinctly and preserve partially received data only under a bounded state machine. Test fragmented TCP delivery, concatenated messages, corrupted lengths, checksum failures, duplicate frames, unknown identifiers, timeouts and reconnects. A single socket read is not guaranteed to contain exactly one application message.

Maintain acquisition time, source time and receipt time separately where available. Convert timestamps using the protocol's epoch and resolution rather than assuming Unix milliseconds. Quality flags can invalidate an otherwise well-formed number. A cached or retained sample should retain its original source timestamp and age; do not relabel it fresh on reconnect. For offline fixtures, verify round-trip encoding only for encodings with a defined inverse, and independently check at least one capture against the vendor's documented example. A round trip between two implementations sharing the same mistaken convention is insufficient evidence.
