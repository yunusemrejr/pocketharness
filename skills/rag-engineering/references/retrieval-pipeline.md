# Retrieval pipeline and context budgets

Create a document contract before indexing: canonical identity, version or content hash, source URI, ingestion timestamp, valid-time interval if known, access metadata, parser version and source ranges. Keep raw originals recoverable. A parser that flattens a table can invert a claim by separating a value from its column header; preserve row labels, units, footnotes and section ancestry. For PDFs, track physical page indices separately from printed page labels.

Choose chunk boundaries around coherent units such as sections, paragraphs, functions or table regions. Benchmark candidate sizes on actual query types rather than treating one token count as universally optimal. Overlap can preserve boundary context but also wastes prompt tokens and inflates duplicate retrieval. Parent-child retrieval can search smaller units and expand only the needed surrounding context. Store source offsets so expansion remains traceable and does not accidentally join unrelated versions.

Use lexical search for exact identifiers, error codes, names and quoted phrases, with semantic retrieval for paraphrases when the corpus supports it. Hybrid fusion should combine ranks or otherwise calibrated scores; raw BM25 scores and vector similarities are not directly interchangeable. Reciprocal rank fusion uses reciprocal terms based on each result's rank. Its candidate-window and fusion choices still need workload evaluation. [Elastic RRF documentation](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/reciprocal-rank-fusion).

Apply metadata restrictions, including authorization and valid document versions, consistently to every retrieval branch. Deduplicate by canonical document and passage range before spending the context budget. Rerank a bounded candidate set when measured quality justifies its latency; record the model and preprocessing version. Query rewriting must retain exact identifiers, negations, dates and entity constraints. Keep the original query and compare recall before trusting an expansion that introduces new terms.

Assemble evidence under a token budget measured with the target tokenizer when available. Budget instructions, query, citations, tool schemas and answer headroom as well as passages. Select evidence for coverage and diversity rather than sending the top near-duplicate chunks. Include necessary exceptions and neighboring definitions. If the relevant excerpt cannot fit, return a recoverable reference and a bounded expansion path instead of silently truncating the qualifying sentence.

Carry `{document_id, version, range, retrieved_at}` through retrieval, reranking and answer citation. A stable citation identifier should resolve to the exact version used, not the latest mutable URL. Preserve contradictory evidence explicitly; ranking alone does not decide which statement is authoritative. For versioned operational documentation, prefer the version compatible with the user's system and explain any mismatch. Cache embeddings by normalized content and embedding-model version, but do not confuse an embedding cache hit with an authorized or current answer cache hit.
