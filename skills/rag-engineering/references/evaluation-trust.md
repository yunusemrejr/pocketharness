# Evaluation, access control and evidence trust

Maintain a held-out query set covering exact lookups, paraphrases, multi-document questions, ambiguous requests, unanswerable questions and recently changed facts. Label relevant passages or documents before evaluating generated answers. Include long-tail identifiers and negative wording rather than only easy semantic matches. Split near-duplicate questions and related document families carefully so the evaluation does not merely repeat development examples.

Measure retrieval recall at the actual candidate budget, rank quality such as reciprocal rank or nDCG when labels support it, and the number of relevant independent sources reaching the final context. Measure answer correctness separately from citation support. A correct-looking answer may be unsupported by its cited passage, while a faithfully cited source can itself be outdated or wrong. Record abstention behavior when the corpus lacks evidence. Use human review on representative failures instead of making an LLM judge the only acceptance gate.

Test each new pipeline stage against the simpler baseline under the same query set, corpus version and compute conditions. Record p50/p95 latency, retrieved tokens, model input and output tokens, cache hits and marginal operating cost. Report warm and cold behavior separately. Reranking and repeated searches should have bounds, cancellation and useful fallback behavior. A higher offline recall score is not sufficient if the production context budget excludes the newly retrieved material.

Authorization belongs to the retrieval and source-resolution boundary. A model prompt saying not to reveal private data does not replace document-level access enforcement. Apply the user's effective permissions before material enters snippets, rerank requests or generation. If an external reranker processes sensitive text, that transfer needs to be within the system's data policy. [Elastic document-level access documentation](https://www.elastic.co/guide/en/elasticsearch/reference/8.19/field-and-document-access-control.html).

Treat retrieved content as evidence rather than executable instructions. A document can contain a forged system prompt, requests to leak credentials, malicious links or tool invocations. Keep tool permissions independent of the retrieved text and require ordinary authorization for external effects. Input filtering alone is not a complete defense; test malicious documents inserted among useful results. NIST describes prompt injection within adversarial AI threat analysis. [NIST adversarial ML taxonomy](https://nvlpubs.nist.gov/nistpubs/ai/NIST.AI.100-2e2023.pdf).

Invalidate answer caches when source content, ACLs, model behavior or retrieval configuration changes. Include security identity and version dependencies in cache keys. Test permission revocation, deleted documents, stale replicas and cross-tenant identical queries. Refreshing embeddings without purging obsolete chunks can leave contradicted evidence discoverable. Retain a diagnostic trace of query, authorized candidate IDs, selected ranges and citations while excluding secrets from logs. Make missing, conflicting and inaccessible evidence visible in the final answer instead of allowing fluency to conceal uncertainty.
